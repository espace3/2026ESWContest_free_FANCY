# 각도 정확도 캘리브레이션

목표: **위치 정확도 < 2°** (팀 성능 목표). 지금은 리밋 스위치도 엔코더도 없는 완전
오픈루프라, 각도가 안 맞아도 시스템이 스스로 알아채지 못한다.

이 문서의 요점은 하나다. **"각도가 안 맞는다"는 증상 하나에 원인이 네 가지 있고,
증상만 봐서는 구분이 안 된다.** 값을 감으로 고치면 한 오차를 다른 오차로 덮어서
조건이 바뀌는 순간 다시 틀어진다 (예: 백래시를 기어비로 보정하면 같은 방향 이동은
맞고 왕복은 더 틀어진다). 아래 순서대로 좁힐 것.

---

## 1. 오차원과 각각의 지문

| 오차원 | 무엇 | **지문 (이걸로 가른다)** | 어디서 고치나 |
|---|---|---|---|
| **A. 스케일 (기어비)** | `gear_ratio`가 실제와 다름 | **회전량에 비례.** 360°에서 3° 틀리면 1080°에서 9° | `config.py` `stepper.*.gear_ratio` |
| **B. 백래시** | 기어 유격 — 방향을 바꿀 때 그만큼 헛돎 | **방향 전환 횟수에 비례, 회전량과 무관.** 한 방향으로만 돌면 안 나타남 | 코드 (반전 시 보정 스텝) |
| **C. 탈조** | 스텝을 잃음 | **비재현적, 누적.** 같은 명령을 반복하면 매번 다르고 점점 커짐. 속도·부하 의존 | `f_max` 하향 / 전류 / 램프 |
| **D. 원점 오차** | `home()`이 "지금 여기가 0°"라고 선언할 뿐 | **상수 오프셋.** 모든 각도가 같은 양만큼 밀림 | 물리 마커 정렬 |

**핵심 판별식**

```
같은 방향으로만 크게 돌렸을 때 오차가 회전량에 비례하는가?
├─ 예   → A. 기어비
└─ 아니오(상수) → 방향을 바꿀 때만 생기는가?
                  ├─ 예   → B. 백래시
                  └─ 아니오 → 반복하면 매번 달라지는가?
                              ├─ 예   → C. 탈조
                              └─ 아니오 → D. 원점
```

> 참고: 팬은 2026-08-07에 이미 한 번 갈랐다 — 360° 명령에 오차 3°, **1080°에서도 3°**.
> 비례하지 않으므로 기어비가 아니라 백래시/원점이다 (`docs/lgpio_patch.md`의
> 배제된 가설 표). 틸트는 미실시.

## 2. 측정 도구부터 (이게 없으면 아무것도 못 잰다)

### 레이저 + 벽 (틸트, 그리고 팬의 작은 각도)

헤드에 레이저 포인터를 붙이고 벽에 쏜다. **거리가 증폭기 역할을 한다.**

```
벽까지 거리 D, 벽에서 점이 움직인 거리 x  →  각도 θ ≈ 57.3 × x / D  (도)
```

- D = 2m에서 **1° = 3.5cm**. 자로 mm까지 읽으면 분해능 0.03° — 목표 2°에 대해 과잉이다.
- 큰 각도에서는 `tan`을 써야 한다: `θ = atan(x/D) × 57.3`. 10° 넘으면 위 근사가 1% 이상
  틀어진다. 틸트는 리밋이 ±15°라 **`atan`으로 계산할 것.**
- 레이저는 헤드 회전축과 나란하게. 비스듬하면 그 자체가 스케일 오차로 보인다.

### 눈금판 (팬의 큰 각도)

팬은 ±100°까지 도니 레이저로는 못 잰다. **베이스에 각도 눈금을 인쇄해 붙이고 헤드에
지시선**을 그린다. A4에 원형 각도기를 인쇄하면 1° 눈금은 충분히 읽힌다.

### 0° 물리 마커 (필수, 먼저)

헤드와 베이스 양쪽에 0° 표시를 한다. `home()`은 "**지금 이 자리를 0°라고 선언**"할
뿐이므로, 마커에 정확히 맞춘 상태에서만 불러야 한다. 이게 없으면 D를 영원히 못 가른다.
`restore_origin()`의 복원 결과를 눈으로 대조하는 데도 같은 마커를 쓴다.

## 3. 실험 순서

**순서를 지킬 것.** A를 확정하기 전에 B를 재면 스케일 오차가 백래시로 둔갑한다.

### 실험 0 — 원점 맞추기 (매 실험 시작 전)

헤드를 손으로 0° 마커에 맞춘 뒤:

```bash
python bench/motor_drive.py --axis pan --deg 0     # 시작 시 home()으로 장부 0 확정
```

### 실험 A — 스케일 (기어비)

**같은 방향으로만** 크게 돌린다. 되돌아오는 이동에서 측정하면 백래시가 섞인다.

```bash
python bench/motor_drive.py --axis pan --deg 360    # 읽고 기록, 0으로 되돌리지 말고
python bench/motor_drive.py --axis pan --deg 720    # 이어서 (누적 720)
python bench/motor_drive.py --axis pan --deg 1080   # 이어서 (누적 1080)
```

각 지점에서 **물리 각도 − 명령 각도**를 기록한다.

| 판정 | 뜻 |
|---|---|
| 오차가 360:720:1080 = 1:2:3 으로 커짐 | **기어비 오차.** 아래 식으로 보정 |
| 오차가 대체로 일정 | 기어비는 맞다 → 실험 B로 |

**보정식** (실측 = 실제로 돌아간 각도, 명령 = 시킨 각도):

```
gear_ratio_new = gear_ratio_old × (명령각 / 실측각)
```

예: `gear_ratio` 100으로 1080° 명령에 1069°만 돌았다면 → `100 × 1080/1069 = 101.03`.

> 팬은 소프트 리밋 ±100°(config `limits`)에 걸리므로, 이 실험은 리밋을 임시로 넓히거나
> `bench/motor_drive.py`처럼 clamp를 거치지 않는 경로로 해야 한다. **조립 후에는 배선이
> 꼬이므로 프레임 간섭을 눈으로 확인하며 돌릴 것.**
>
> 틸트는 ±15°라 큰 각도를 못 돈다. `gear_ratio` 92.6은 **팬 헤드를 떼고 벤치에서** 잰
> 값이므로(라벨은 100), 재확인하려면 헤드를 분리하고 `--deg 720`으로 같은 절차를 밟는다.
> **부하를 걸었을 때 값이 달라지면 기어박스 내부 미끄러짐**이므로 보정이 아니라 교체 검토다.

### 실험 B — 백래시

같은 목표 지점을 **양방향에서 접근**해 그 차이를 잰다.

```bash
# + 방향에서 접근
python bench/motor_drive.py --axis tilt --deg -10   # 여유 있게 아래로
python bench/motor_drive.py --axis tilt --deg 0     # 위로 올라와 0°에서 정지 → 위치 읽기

# - 방향에서 접근
python bench/motor_drive.py --axis tilt --deg 10    # 여유 있게 위로
python bench/motor_drive.py --axis tilt --deg 0     # 내려와 0°에서 정지 → 위치 읽기
```

**두 위치의 차이 = 백래시.** 여러 각도(0°, ±5°, ±10°)에서 3회씩 반복해 평균과 산포를
본다. 값이 각도마다 크게 다르면 기어 편심이라 단순 보정으로는 못 잡는다.

- 틸트(웜기어)는 백래시가 크게 나오기 쉽다 — TODO의 미실측 항목이다.
- 팬은 위 2026-08-07 관측(상수 3°)이 이 실험에서 재현될 것으로 예상된다.

**보정**: 방향 반전 시 백래시만큼 추가 스텝을 보낸다. `motor_controller.py`의 반전 경로
(감속 → drain → DIR 변경 → 가속)에서 DIR 변경 직후에 넣으면 된다. **장부에는 그 스텝을
반영하면 안 된다** — 헛도는 구간이라 실제 출력축은 안 움직이기 때문이다. 이건 "장부 =
송출 확정 위치"라는 현재 불변식을 깨는 유일한 예외라서, 구현할 때 주석으로 남길 것.

### 실험 C — 반복성 (탈조)

```bash
python bench/motor_drive.py --axis pan --sweep 60 --cycles 10 --timing
```

끝난 뒤 0° 복귀 위치를 시작 마커와 대조한다.

| 판정 | 뜻 |
|---|---|
| 사이클을 늘릴수록(5 → 10 → 20) 오차가 커짐 | **탈조.** `f_max` 하향 / 램프 완만하게 / 드라이버 전류 확인 |
| 사이클 수와 무관하게 일정 | 백래시 (왕복 1회당 고정량) |
| 매번 값이 다름 | 탈조 또는 기구 미끄러짐 |

`--timing`을 같이 켜서 **언더런이 0인지** 본다. 언더런이 있으면 펄스가 끊긴 것이라
탈조 원인이 기구가 아니라 타이밍 쪽이다 (`docs/lgpio_patch.md`).

부하 조건을 바꿔가며(팬 헤드 장착 전/후, 추적 스크립트 동시 실행) 반복할 것 — 탈조는
부하 의존이다.

### 실험 D — 원점

A·B·C를 다 잡은 뒤에도 **모든 각도가 같은 양만큼** 밀려 있으면 원점이다. 헤드를 마커에
다시 맞추고 `home()`부터 다시.

## 4. 보정을 어디에 넣나

| 오차원 | 위치 | 주의 |
|---|---|---|
| A 기어비 | `config.py` `stepper.pan/tilt.gear_ratio` | 바꾸면 `deg_per_step`이 따라 바뀌므로 **저장된 `motor_state.json`의 스텝값이 다른 각도를 뜻하게 된다.** 캘리브레이션 후에는 상태 파일을 지우고 원점부터 다시 잡을 것 |
| B 백래시 | `motor_controller.py` 반전 경로 | 장부에 반영 금지 (위 참고). config에 `backlash_deg`로 값만 두고 코드가 읽게 |
| C 탈조 | `config.py` `f_max` / `ramp_*`, 드라이버 전류(VREF) | `f_max`를 내리면 속도를 잃는다. 마이크로스텝 1/16→1/8이 대안 (같은 각속도에 펄스 절반) |
| D 원점 | 물리 마커 + `home()` 호출 절차 | 근본 해결은 호밍 하드웨어 (TODO: 리밋 스위치 / AS5600 엔코더 / StallGuard / ArUco 마커) |

## 5. 기록

실험할 때마다 **날짜·축·부하 조건(헤드 장착 여부)·f_max·명령각·실측각**을 남길 것.
틸트 `gear_ratio` 92.6이 "무부하 벤치 실측"이라는 단서 없이 숫자만 남았다면 지금 그 값을
믿어야 할지 몰랐을 것이다. 조건이 빠진 실측값은 나중에 다시 재야 한다.
