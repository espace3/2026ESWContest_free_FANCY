# BLE 프로토콜 (RPi 구현 기준)

> 원본 명세는 **앱 저장소**(`apps/ESW_BLE_app/docs/ble_protocol.md`)에 있다.
> 이 문서는 그 명세를 RPi 쪽에서 **실제로 구현한 결과**를 정리한 것으로,
> 값·바이트 형식은 `main.py`의 `EswFanService`가 기준이다.
> 둘이 어긋나면 앱 저장소의 명세가 우선이며, 이 문서와 코드를 함께 고친다.

- 역할: **RPi = Peripheral(GATT 서버)**, 앱 = Central
- Advertising 이름(앱에서 검색되는 이름): `ESW-FAN`
- 스택: BlueZ 5.x + `bluez_peripheral`(dbus_fast)

## 1. UUID

베이스: `14d7{XXXX}-7197-49e5-a017-0b2f308120f0`

| 이름 | 단축 | 속성 | 길이 |
|---|---|---|---|
| Service | `0x0001` | — | — |
| POWER | `0x0002` | Write | 1 byte |
| MODE | `0x0003` | Write | 1 byte |
| WIND | `0x0004` | Write | 2 bytes |
| STATUS | `0x0005` | Read \| Notify | 가변 |

## 2. 앱 → RPi (Write)

### POWER `[전원]`
| 값 | 의미 |
|---|---|
| `0x00` | OFF |
| `0x01` | ON |

전원 OFF는 풍속을 정지시키고 헤드를 0°,0°로 파킹한다.

### MODE `[모드]`
| 값 | 의미 |
|---|---|
| `0x00` | 기본-고정 |
| `0x01` | 기본-회전 |
| `0x02` | 타겟 (가슴 중심 추적) |
| `0x03` | 타겟-부위 (머리/상체/하체 순찰) |

### WIND `[대상, 세기]`
| 대상 | 의미 | 세기 |
|---|---|---|
| `0x00` | 공용 | `0x00`(정지) ~ `0x03`(강풍) |
| `0x01` | 머리 | `0x00` ~ `0x03` |
| `0x02` | 상체 | **`0x01` ~ `0x03`** (정지 불가) |
| `0x03` | 하체 | `0x00` ~ `0x03` |

세기: `0`=정지, `1`=미풍, `2`=약풍, `3`=강풍.

**상체 `0x00`은 거부된다.** 부위 순찰 경로가 비지 않도록 하는 보장이다
(순찰은 세기 0인 부위를 건너뛰므로, 전 부위가 0이면 돌 곳이 없어진다).

## 3. 설정의 주체는 앱이다

RPi는 세기를 **스스로 바꾸지 않는다.** 세기가 바뀌는 경로는 WIND write **하나뿐**이고,
모드/전원 전환은 게이팅(전원 OFF → 0, 부위 모드 → 러너가 소유)만 한다.

따라서 **모드 전환 직후의 세기는 앱이 화면 표시값을 재전송해 맞춘다.** 앱이 재전송하지
않는 과도기에는 전환 전 세기가 그대로 유지된다. (한때 RPi가 모드별 세기를 저장해 두고
전환 시 자동 재적용했는데, 앱 화면과 실제 동작이 어긋나는 원인이라 폐기했다.)

## 4. RPi → 앱 (STATUS)

첫 바이트가 payload 종류를 가리킨다.

### Read — `0x04` 스냅샷 (8 bytes)
```
[0x04, 전원, 요청 모드, 유효 모드, 공용 세기, 머리 세기, 상체 세기, 하체 세기]
```
앱이 재전송 직후 자기 표시값과 대조하는 **불일치 검증용**이다. 주체는 앱이므로
앱이 이 값을 따라가지 않는다 — 다르면 앱이 재전송으로 교정한다.

### Notify — `0x01` 에코백
```
[0x01, Characteristic 번호, 원본 바이트...]
```
Characteristic 번호: POWER=`1`, MODE=`2`, WIND=`3`.

**적용된 write에만 에코가 나간다. 거부된 write는 에코가 없고, 앱이 타임아웃으로 감지한다.**
에코는 적용(러너 전환)보다 **먼저** 보낸다 — 러너 전환은 이전 스레드 join으로 수 초가
걸릴 수 있어, 뒤에 보내면 앱의 에코 타임아웃이 모드 전환마다 오탐한다.

### Notify — `0x02` 객체 인식
```
[0x02, 0 | 1]
```
사람이 인식되는지 여부. **바뀔 때만** 보낸다.

### Notify — `0x03` 유효 모드 push
```
[0x03, 모드]
```
**요청 모드**(앱이 write한 값)와 **유효 모드**(RPi가 실제로 돌리는 모드)는 다를 수 있다.
부위 모드(`0x03`)에서 사용자가 이동해 추적 폴백으로 넘어가면 유효 모드가 `0x02`가 되고,
다시 잠잠해지면 `0x03`으로 돌아온다. 그 전환마다 이 push가 나간다.

## 5. 연결 끊김

앱과의 연결이 끊기면 **전원 OFF와 동일하게 처리**한다 (풍속 정지 + 0°,0° 파킹).
끊긴 동안에는 양쪽 다 OFF로 수렴하므로 상태 불일치가 성립하지 않는다.

## 6. 스레드 규칙

`dbus_fast`는 스레드 안전하지 않다. 추적/부위 러너 스레드는 `report_effective()` /
`report_recognized()`로 **보고만** 하고, 서비스가 `loop.call_soon_threadsafe()`로 BLE
asyncio 루프에 넘겨 실제 notify를 보낸다. notify 실패는 로그만 남기고 모터/릴레이 동작에
영향을 주지 않는다.
