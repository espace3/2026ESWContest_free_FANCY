      lgpio 패치 후에도 **팬만** 멎는다. 틸트는 계속 움직이고, 프로세스를 껐다 켜면
      팬이 다시 정상 동작한다 (`verify_track_pantilt.py`로도 재현 — E2E/BLE 무관).
      **소프트웨어 문제가 아니다.** 근거:
      - `--timing`이 팬 구간마다 계속 출력된다 (예: 청크 214개 / 계획 8131ms /
        드리프트 +0.4% / **언더런 0**) = 펄스는 정상적으로 나가는 중
      - 위치 장부도 계속 증가한다 (`pan=-125.64°`까지 감)
      - 그런데 **팬 드라이버 방열판은 차갑고 틸트는 뜨겁다** = 팬 코일에 전류가
        아예 안 흐른다. 소리도 회전도 없다 (탈조라면 시끄럽다)
      - EN은 두 축 공유 핀이라 **소프트웨어로 팬만 통전을 끊을 수 없다**. 복구되는
        유일한 계기가 프로세스 재시작 = `disable()`→`enable()`의 **EN 토글**이라는 점이
        드라이버 내부 보호 래치를 가리킨다
      **실험 표 (2026-08-26)**:
      | 조건 | 결과 |
      |---|---|
      | `verify_motor --axis pan --deg ±90` | 정상 (끝까지 돌아감) |
      | `verify_track_pan` (팬 단독 추적) 3~5분 | 정상 |
      | `verify_track_pantilt --deadzone-tilt 100` (틸트 통전만, 스텝 0) | **정상** |
      | `verify_track_pantilt` (두 축 정상) | **팬 즉시 정지** |
      | 위 + `stepper.tilt.f_max` 6000→3000 | 죽지만 **더 오래 버팀** |
      → 방아쇠는 **두 축이 동시에 스텝을 밟는 것**이고, 틸트 속도를 낮추면 버티는
      시간이 늘어난다(**용량 의존**). 회생 에너지는 속도의 제곱에 비례하므로 전원
      레일 교란(회생 스파이크/전압 강하) → 팬 드라이버 보호 래치로 보고 있다.
      24V 5A SMPS(120W)라 **용량 부족은 아니다.** TMC2209의 VM 절대 최대가 약 29V라
      24V는 여유가 5V뿐이고, SMPS는 회생 전류를 못 받아준다는 점이 근거다.
      **배제된 가설** (같은 길을 다시 걷지 말 것):
      | 가설 | 어떻게 배제했나 |
      |---|---|
      | lgpio 큐 고착 | `--timing` 계속 출력 + 언더런 0. py-spy상 워커도 정상 진행 |
      | 리밋 포화 (`pan=-199.74°`) | 물리 정지 후 장부만 쌓여 리밋에 닿은 **결과**. 양방향 모두 안 움직임 |
      | 탈조 | 무소음. 탈조는 시끄럽다 |
      | 기구 걸림 / 케이블 꼬임 | 정지 직후 `verify_motor --deg ±90`이 끝까지 정상 |
      | 카메라·비전·BLE·릴레이 | `verify_track_pantilt` 단독에서도 재현 |
      | 전원 용량 | 24V 5A = 120W. 두 드라이버 합보다 한참 크다 |
      **다음 (우선순위 순)**:
      1. 각 드라이버 VM 근처 + 전원 입력단에 **벌크 커패시터 470µF/35V 이상 저ESR**
